# A/B VFO 实现设计

2026-10-12，第一阶段记录。2026-10-13 已扩展为 [多 VFO 与双守听](multi-vfo-design.md)，当前格式 7、四个保存项和双守听以新文档为准；下文格式 6／单选接收及后续规划是此前阶段。本文首批范围已实现，主机回归和 ARM 构建通过；尚未刷机验证，双守听仍是后续规划。实现基于 `radio-state`、`rx-runtime`、`tx-runtime`、配置格式 4／5 迁移至 6，以及 28 px VFO 组件规划。

## 目标与首批范围

首批实现两个独立 VFO，同时显示 A/B，通过 `F → 2(A/B)` 切换选中项，硬件只接收选中项。选中项同时决定调谐、参数菜单、频段切换、搜索和 PTT 的归属。A/B 可使用相同或不同频段，解调模式明确，底层沿用现有自动芯片选择。

第二行表示已保存的另一个 VFO，不表示其正在接收。双守听是后续独立阶段，不在首批暗中启动；两个频率使用不同芯片，也不默认同时接收。当前 HAL 切换芯片时会关闭或静音旧路径，音频、静噪和测量仍共用一个硬件上下文。

真实 TX 仍遵循现有硬件能力检查，不因增加 VFO 解锁。频道 Name、Save 继续占位。

## 操作约定

| 操作 | 行为 |
| --- | --- |
| `F → 2` | A/B 切换，成功应用目标接收方案后移动选中箭头 |
| 上／下、数字输入 | 只改变选中 VFO |
| `F → 1`、侧键 1 | 切换选中 VFO 的频段 |
| `F → 0`、侧键 2 | 切换选中 VFO 的模式 |
| 短按 MENU | 打开选中 VFO 菜单，公共标题显示 `VFO A` 或 `VFO B` |
| `F → *` | 只搜索选中 VFO，搜索期间沿用现有取消规则 |
| PTT | 使用按下时选中 VFO 的 RX 方案和该 VFO 的 TX 配置 |
| EXIT | 保持退出／取消语义，不切换 VFO |

搜索、量化确认、输入、菜单、PTT 按住或等待释放期间不处理 A/B 快捷切换。输入回调明确携带或锁定目标 VFO 标识，不依赖回调时可变的全局选中索引。PTT 生命周期内锁定归属，恢复按下前接收方案。

切换成功后显示目标频率至少 1 秒，然后按已有规则显示可用名称／RDS。切换本身不套用频段预设，恢复该 VFO 的全部当前参数。再次进入另一频段才应用共享预设，保持当前频段编辑器的行为。

## 用户状态与共享预设

不直接复制两份完整 `RadioUserState`：该结构同时包含当前状态、九个频段记忆及共享预设，复制会造成预设不同步。

建议明确拆分为：

```c
#define RADIO_VFO_COUNT 2

typedef struct {
  uint8_t active_band;
  BandState current;
  BandState bands[RADIO_STATE_BANDS];
  TxConfig tx;
} VfoConfig;

typedef struct {
  uint8_t selected_vfo;
  VfoConfig vfos[RADIO_VFO_COUNT];
  RadioParameters presets[RADIO_STATE_BANDS];
} RadioUserState;
```

`DeviceConfig` 保留 `radio` 和全局 `preferences`，移除顶层单一 `tx`。各 VFO 独立拥有当前频率、模式、步进、带宽、静噪、RX Tone、TX Enable/Power/Frequency/Tone 和各频段上次成功状态。预设仅存一份；TOT、Busy Lock、显示、按键锁等保持全局。

`radio-state` API 按职责区分整组校验、单 VFO 调谐提交和共享预设操作，显式传入 VFO 标识，更新调用者，不保留旧单 VFO 调用包装。频段编辑器 `Use current` 读取选中 VFO；校验草稿用选中 VFO 的该频段记忆。保存共享预设不立即覆盖任何 VFO，两个 VFO 下次进入该频段才应用。

默认 A 保持现有 145.500 MHz NFM；新建 B 使用内置 70cm 初始频率与预设，TX Off、Low、Tone Off、Frequency Same。旧配置迁移时 A 完整继承原状态及 TX 配置，B 使用共享预设初始化其频段记忆，再选中 70cm；选中 A。初始化使用频段定义中的初始值，不在多个文件重复频率常量。

## 运行时和失败处理

保留一份物理接收 `RadioState`、一份 `RxRuntime`、一份 `TxRuntime` 和一份当前接收路径的 RDS 解析器。另有 `UI_VfoState[2]` 负责各行独立动画；按 VFO 保存已确认的显示文本缓存，并标记所属频率，不能把 A 的 RDS 显示到 B。

新增明确的接收归属标识 `receiving_vfo`，与用户选择标识区分：关闭接收或调谐失败时允许“没有接收归属”。硬件测量、RX 指示、信号图标只能交给实际接收归属。非活动行不沿用最后的信号读数。

A/B 切换按以下顺序执行：

1. 校验目标 VFO 和 RX 方案，先不改变选中索引及配置。
2. 暂停旧音频，调用现有 `RX_RuntimeTune` 应用目标。
3. 成功后提交选中索引及接收归属，重置 RDS 硬件轮询状态、频率停留计时和测量有效性，并请求延迟保存。
4. 应用失败且旧方案恢复成功：选中项保持原值，提示 `Tune failed`；失败且恢复失败：保持原选择，清除接收归属，静音并提示 `RX error`。

目标方案本身不支持（芯片、补丁或模式缺失）时切换失败并保留原项，不静默改变目标模式。选中 VFO 手动调到无接收路径的频率时，继续沿用现有“可导航目标但不作为成功调谐持久化”的规则；这是 UI 草稿，不可污染另一个 VFO 的有效状态。

开机恢复最后选中 VFO；若无法接收则明确显示不可用，不静默切到另一项或修改模式。切换、搜索临时方案及失败回滚不改写 VFO 的频段记忆；成功调谐才提交。搜索成功只保存所属 VFO，取消仅恢复搜索开始时的方案。

## 首屏与提示

公共状态栏仍占 y=0..7。A 放 y=8..35，B 放 y=36..63，复用现有 `UI_VfoRender`，不缩小字体。每行保留黑底标题、完整频段名、模式、频率／名称切换及活动区域。

选中箭头表示操作归属，RX／TX 表示实际活动。首批非选中行左侧显示步进，不显示 RX、有效信号或虚假的不可用提示；可接收性错误只在已尝试应用后标记。组件动画、频率停留及滚动互不重置。

两行用满 64 px，目前 `PrintSmall(0, 43, ...)` 的通知会覆盖 B，不能继续使用。临时提示改由公共状态栏替换标题显示，超时恢复；F 图标与电池等保留既有布局。参数菜单、输入和确认界面仍全屏。不新增底部提示条。

## 存储格式与迁移

升级至格式 6，继续使用 512 字节×2 的固定槽地址、递增序号、CRC 和回读校验，显式逐字段编码，不序列化 C 结构。

按现有九个频段计算：

| 字段 | 字节 |
| --- | ---: |
| 头部 | 16 |
| VFO 数量及选中索引 | 2 |
| 每 VFO：active_band 1 + current/bands 10×16 + TX 8 | 169 |
| 两个 VFO | 338 |
| 共享预设 9×10 | 90 |
| 全局 preferences（现有 18 + TOT 2 + Busy Lock 1） | 21 |
| 总计 | **467** |
| 单槽剩余 | **45** |

BandState 的 16 字节包含频率、步进、带宽、模式、静噪及 RX Tone；共享预设的 10 字节带宽沿用当前 uint16 编码限制。以上是磁盘格式预算，不是 C 结构 RAM 大小。用静态断言核对实际编码长度。

保留格式 4、5 解码及 CRC 校验，迁移仅在内存完成，后续正常保存写入格式 6。加载旧数据不立即重写两槽，不全片擦除；第一次新格式提交仍保留旧有效槽。损坏和未知格式维持当前显式初始化流程。新固件写出格式 6 后旧固件无法读取新记录，不承诺降级兼容。

## 实施顺序和验收

1. **模型及持久化**：拆分共享预设与两份 VFO 配置，完成格式 4/5→6 迁移和双槽断电恢复；同步改造频段编辑器、TX 读取及所有单 VFO 配置调用。
2. **应用运行时**：将 `apps/vfo1.*` 改为 `apps/vfo.*`，统一更新应用入口和调用者；引入明确归属、切换事务、两份 UI 状态及回调目标，保留一个 RF 运行时。
3. **按键和双行显示**：接入 F→2、双组件、菜单标题、状态栏通知及 RDS 文本归属。更新真实帧缓冲预览。
4. **验证和文档**：检查回归与固件体积，同步用户手册、UI 布局及重构进度；实现后才能把当前行为描述改为双 VFO。

验收覆盖：A/B 参数互不串写；同频段不同模式独立恢复；共享预设不即时覆盖当前参数；同芯片及跨芯片切换；调谐失败恢复与双失败静音；无接收路径、缺补丁；开机恢复选择；格式 4/5 迁移、坏槽及写入失败；输入／搜索／PTT 归属；RX 与 RSSI 不串行；RDS 不跨 VFO／频率污染；两行滚动隔离；提示不遮盖 B。

RAM 增量包括第二 VFO 频段记忆、第二组件动画和文本缓存，实施时以链接结果及栈需求核算。Flash 预算采用新构建结果，不能沿用主设计中的历史数字。优先复用现有组件和解析器，不创建两个完整接收器实例。

## 后续双守听

在上述状态和归属稳定后再增加有界守听调度器。用户选中项保持操作／PTT 主 VFO，调度器可暂时改变接收归属，不改变选中箭头。定义稳定等待、轮询周期、信号保持、静噪／亚音判定、返回主 VFO、手动操作抢占与同频去重；参数由硬件测量确定，不先硬编码未经验证的快速切换周期。

尤其需要评估 SI AM／WFM／SSB 切换与补丁加载成本、SI 断电策略以及共用音频路由。首批不混音、不声称 BK/SI 同时接收。PTT、搜索、输入、调谐和设置期间暂停调度，释放后恢复；SQ0 的常开音频不能简单视为可无限占用的有效信号。守听失败须有界退避，禁止循环占满主调度。

## 实现证据

- `core/radio-state.*`：两份 `VfoConfig`、共享 presets，显式 VFO 标识的状态 API。
- `core/config-store.*`：格式 6、467 B 编码、格式 4／5 解码与迁移、原址双槽。
- `apps/vfo.*`：F→2 切换事务、输入归属、PTT 互斥、两个组件与信号／RDS 归属。
- `tests/vfo-regression.c`：A/B 调频、同频段不同参数、选中 B 重启、失败恢复／双失败、缺补丁、RDS 缓存及过期、输入／搜索／确认／菜单／PTT 互斥、B 的 TX 恢复。
- `tests/config-store-regression.c`：两份 RX/TX 和选择读写，格式 4／5 迁移，非法索引，首次升级写入中断与旧槽恢复。
- `tests/band-editor-regression.c`：B 的 Use current 和共享预设保存隔离。
- 双行像素布局继续由组件回归验证，当前首屏预览见 `docs/images/ab-vfo.png`。

执行 `sh tests/run.sh`、`make -j4`。硬件切换的音频、时延及实机掉电恢复仍需设备验收，主机测试不作为 RF 实测证据。

本次 ARM 构建：Flash 48,348 / 61,440 B，静态 RAM 5,304 / 16,384 B。用同目标 `-Os -fshort-enums -fstack-usage` 对配置模块单独编译（未使用 LTO）得到 CONFIG_Save 栈帧 2,368 B、slotRead 528 B、CONFIG_Decode 672 B、decodePreferences 72 B；该模块嵌套读取路径约 3,640 B，另需预留调用者及 EEPROM／总线栈。这是编译器静态估算，不是整机栈峰值实测。
