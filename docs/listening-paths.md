# 多槽收听路径：四个判断

2026-10-19，按用户确认的简化规则实施。

**选中槽先接收；兼容路径才守候；同一 BK 的事件槽轮询；扬声器始终只播放一路。选中的 BK SQ0 连续收听独占 BK，不再周期性切出去检查其他槽。**

## 1. 决策顺序

| Y/N 询问 | Y | N |
| --- | --- | --- |
| 目标方案可接收吗？ | 准备目标 | 拒绝切换，保留原有效接收 |
| 两个槽使用同一颗芯片吗？ | BK SQ>0 槽轮询；连续收听只保留一路 | 检查路径兼容性 |
| 两条路径能同时工作吗？ | 各自接收 | 选中槽独占，另一条暂停 |
| BK 守候槽有有效通话吗？ | 临时接管音频，结束及回复窗口后恢复 | 保持辅助常驻音频或静音 |

模式、频率、带宽、亚音与硬件能力共同决定 RxPlan，不能为了守候换用不支持的解调器。单槽和多槽使用相同的有效方案检查。

## 2. 组合结果

| 配置 | 选中槽／情况 | 实际行为 |
| --- | --- | --- |
| K1 A=FM，B=BK | A | BK1080 接收；BK 不参与轮询 |
| K1 A=FM，B=BK | B | BK1080 进入待机，BK4829 接收 B；无信号也不自动返回 A |
| K1 A=FM，B/C=BK 事件源 | B 或 C | FM 暂停，B/C 在 BK 上轮询；选回 A 则只接收 FM |
| 任意板，多路 BK SQ>0 | 有效且不重复的方案 | 同芯片轮询；首个确认通话锁定到结束及回复窗口 |
| 任意板，选中 BK SQ0 | 无论还有多少其他槽 | 当前 BK 连续收听；其他槽暂停，没有“听一秒再轮询” |
| K6 BK＋SI，SI 常驻＋BK 事件源 | 任意这些槽 | SI 保持调谐，BK 轮询；通话切音频，结束后返回 SI，无需重载 SSB 补丁 |
| K6 BK＋SI，多个 SI 台＋BK 事件源 | 选中 SI 台 | 该 SI 台常驻，其他 SI 台暂停，BK 事件仍轮询 |
| K6 BK＋SI，多个 SI 台＋BK 事件源 | 选中 BK 事件槽 | 槽序第一路 SI 台常驻；BK 事件轮询 |
| 非选中的 BK SQ0＋SI 常驻＋BK 事件源 | 选中 SI 或 BK 事件 | 非选中的 SQ0 暂停，不抢占 BK；SI 常驻与 BK 事件照常工作 |
| 去重后只有一路，或只有多路连续源 | 任意 | 保持选中槽单路接收，不启动无效守候 |

K1 的 BK1080 和 BK4829 共享互斥前端，不能仅凭两颗芯片推断能并行。K6 BK＋SI 按当前板级能力允许独立接收；扬声器仍只选一路。K6 BK＋BK1080 是否可并行同样由板级接线能力决定，不能从芯片数量推导。本项目当前探测在找到 BK1080 时不再探测 SI，不声明三芯片并行。

## 3. 各模块只负责一件事

- `core/radio-model`：方案是否有效、应该走哪颗芯片。
- `RX_DEVICE_CanRunTogether(a,b)`：不同芯片是否有板级前端冲突；同一芯片返回不能同时运行，同 BK 事件槽由调度器分时处理。
- `core/watch`：一路辅助常驻源、BK 事件轮询、通话锁定和回复窗口。已删除 BK HOME 放音周期与 visited 计数。
- `RX_DEVICE_Activate(plan)`：选中槽的前台接收，先停用其他路径，再准备目标，始终先静音。
- `RX_DEVICE_Prepare(plan)`：后台准备，拒绝冲突，不停止兼容芯片；BK 模式配置不再打开 AF，避免和 SI 混音或反复中断广播。
- `RX_DEVICE_RouteAudio(device,open)`：先关闭功放、静音已启用的输出，仅接通选中的一路，再开功放。路由失败时保持静音。
- `RX_DEVICE_StopChip(device)`：明确停用路径，只有停用成功才清除实际启用记录。BK1080 的静音与待机使用不同入口。

用户选中的槽、芯片启用记录、当前音源分别保存。调用方不再向准备接口传入猜测的 previous chip；设备层用一个启用位图记录可能仍活动的路径，包括失败后需要清理的半完成路径。

## 4. K1 双向切换

FM → BK：关闭功放 → BK1080 待机成功 → 释放 FM 占用 → 恢复 BK RX、解调、带宽、AGC、静噪、亚音与目标频率 → 按静噪条件连接 BK 音频。

BK → FM：关闭功放 → 停止 BK 接收并使其方案缓存失效 → 保留 FM 所需 BK GPIO 控制并选择 VHF 前端 → 启动并调谐 BK1080，准备期间静音 → 接通 FM 音频。

`BK1080_Mute(true)` 仅静音；`BK1080_Standby()` 停止接收，成功后才清调谐缓存和路径占用。待机失败时不得继续调谐冲突的 BK；主槽切换失败沿用已有接收事务恢复旧方案，无法恢复时显示 RX error。

手动切槽立即准备新目标，已有自动通话也可被手动打断。约 2 秒后恢复新兼容组的守候。K1 选中 BK 后 FM 始终被排除；K6 选中 BK 事件槽后，无通话时可以再次听到 SI 常驻台，但 BK 仍参与守候。选中位置与出声音源分别显示。

## 5. FC、Seek、频谱与 PTT

- FC 也询问路径兼容性：K1 从 FM 进入 FC 必须暂停 FM，取消时重新激活 FM；K6 独立 SI 可继续接收和播放。
- 频谱独占 BK 接收操作，入口检查停用结果，退出后恢复主槽方案。
- Seek 独占被搜索的芯片；取消或结束使用原有接收事务恢复，不中途保存用户配置。
- PTT 沿用现有资格和回话规则，暂停守候后发射；释放或超时恢复接收。K1 TX 继续禁用。
- 背景静音不等于空闲退出。SI 仍参与守候时只让出音频，不应用空闲断电偏好；真正退出该路径时才应用 Mute / Power off。

## 6. 验证边界

主机回归覆盖：K1 三槽 FM＋BK＋BK 筛选和手动切换、选中 SQ0 独占、FM↔VHF/UHF 各轮切换共 20 次、BK1080 待机 NACK 时阻止 BK 调谐、FC 共享前端及恢复、SI 后台接收与 BK 音频接管、SSB 保持、失败冷却，以及功放开启时只有一个有效输出。芯片测试区分真实 I²C 的 mute／standby 写入，并验证失败不清缓存、恢复同频仍重新唤醒调谐。

主机模型不代表实机天线和音频验收。HAL／驱动改动必须双板构建，共享功能仍按 K6 的 60 KiB Flash／16 KiB RAM 预算；K1 与 K6 的连续切换、语音和接收恢复分别记录实机结果。
