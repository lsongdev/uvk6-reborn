# UV-K1 硬件事实

更新于 2026-10-19。本文记录用户新购的泉盛 UV-K1「MiniKong」。它**不是**本项目当前的固定开发设备；开发基线仍是 [UV-K6 512 大内存版](hardware-uvk6.md)。本文区分三类证据：**本机实测**（经 USB 只读读取）、**参考固件源码**（他人移植固件中的接线，未经本机 PCB 测量）和**厂家／社区资料**。

## 1. 本机实测（2026-10-19，正常开机模式，只读）

| 项目 | 结果 | 证据 |
| --- | --- | --- |
| USB 枚举 | 厂商 `QUANSHENG`，产品 `K1 CPS`，VID `0x36B7`、PID `0x0001`，bcdDevice 1.00，序列号 `2025080801` | macOS IORegistry |
| USB 类型 | 全速（12 Mbit/s）复合设备（bDeviceClass 0xEF/02/01），接口 CDC ACM（02/02/01），macOS 显示为 `/dev/cu.usbmodem20250808011` | IORegistry；**数据线直接接 MCU 的 USB**，不经过 USB 转串口芯片 |
| 原厂固件版本 | **7.02.07** | `0x0514` hello 的应答 `0x0515` |
| 串口协议 | 与 UV-K5 原厂相同：`AB CD` 帧头，16 字节 XOR 混淆表，CRC16/XMODEM，`DC BA` 帧尾；CDC 端口忽略波特率 | `tools/flash.py` 的帧函数可直接收发 |
| hello 附加字段 | AES key 标志 = 0，锁屏 = 0；版本字段 16 B 中 `7.02.07` 后紧跟 `63 7C 77 7B F2 6B`（AES S-box 首字节），说明原厂未清零缓冲区 | `0x0515` 原始应答 |
| EEPROM 读命令 | `0x051B` 支持 16 位地址，单次 128 B；`0x0000–0xFFFF` 两次读取逐字节相同 | 见 §4 |

本次没有发送任何写命令。

### Bootloader（2026-10-19，只监听）

K1 按住 PTT 开机进入刷机模式后，经 **K 头 UART 线**（`/dev/cu.usbserial-1420`，38400 baud）持续广播 `0x0518`，帧格式与 UV-K5/K6 相同（XOR 混淆、CRC16）。本次只接收，未回复 `0x0530` 握手，也未发送任何数据。

| 字段 | 值 |
| --- | --- |
| Bootloader 版本 | **7.02.02**（UV-K6 为 3.00.02） |
| UID（16 B） | `54 34 50 41 08 36 32 33 58 8e 80 00 78 d5 04 56` |
| 原始帧 | `1805 2000` + UID + `372e30322e3032000000` + `c4 20 00 08 00 00` |

参考固件的刷写工具（`tools/serialtool/_prog.py`）使用同一流程：收到 `0x0518` 后回 `0x0530`（Bootloader 版本），再以 `0x0519` 按 256 B 页写入，`0x051A` 应答。两种机型的 Bootloader 版本号前缀不同（3.x／7.x），刷写工具据此识别板型，避免把一种机型的镜像刷进另一种：参考项目记录了把 K1 镜像刷进 UV-K5 V1 后只能拆机经 SWD 恢复的案例。

## 2. MCU 与存储（参考固件源码）

主要依据：[armel/uv-k1-k5v3-firmware-custom](https://github.com/armel/uv-k1-k5v3-firmware-custom)（commit `5fedc09`，2026-10-17），即 F4HWN 的 UV-K1／UV-K5 V3 移植版；其 README 说明这两款机型改用 PY32F071。尚未通过本机芯片丝印核实。

| 项目 | UV-K1 | 本项目 UV-K6 基线 |
| --- | --- | --- |
| MCU | **Puya PY32F071xB**（Cortex-M0+） | DP32G030（Cortex-M0） |
| 内部 Flash | 128 KiB；Bootloader 占 `0x08000000–0x080027FF`（10 KiB），应用从 **`0x08002800`** 起，可用 **118 KiB** | 应用 60 KiB，从 `0x00000000` 起 |
| RAM | 16 KiB（`0x20000000`） | 16 KiB |
| 时钟 | 参考固件按 48 MHz 运行，HSE 宏为 24 MHz | DP32G030 平台配置 |
| 向量表 | 应用设置 `SCB->VTOR`（M0+ 支持） | 位于 0 地址 |
| 外部存储 | **2 MiB SPI NOR Flash，本机 JEDEC ID `EB 60 15`（2026-10-19 自编固件实测）；参考驱动名 PY25Q16**，扇区擦除 4 KiB，页编程 256 B；SPI2：SCK PA0、MOSI PA1、MISO PA2，CS PA3 | I²C EEPROM 512 KiB |
| 射频芯片 | 参考固件只编译 `bk4829.c`，即 **BK4829**（BK4819 的后续型号，寄存器大体相同但有差异） | BK4819 |
| 广播接收 | BK1080，独立软件 I²C：SCL PF5、SDA PF6 | BK1080 或 SI4732 改装 |

社区站点 [uv-k1.com](https://uv-k1.com/) 也说明换用了新处理器，UV-K5 固件不兼容；并提到 UV-K1(8) 有一个带 8 MB Flash 的型号。本机后续用自编只读固件读取 `0x9F`，返回 `EB 60 15`，与 2 MiB 容量相符；芯片厂商/丝印尚未确认，不能仅凭参考驱动名认定为 Puya。

## 3. 引脚（参考固件源码，未经本机通断测量）

依据：参考固件的 `App/board.c`、`App/driver/{gpio.h,st7565.c,py25q16.c,bk4829.c,i2c.c,uart.c,keyboard.c,backlight.c}`。

| 功能 | UV-K1（PY32F071） | UV-K6（DP32G030，见 [hardware-uvk6.md](hardware-uvk6.md#3-引脚键盘与物理标记)） |
| --- | --- | --- |
| LCD SPI | SPI1：SCK PA5、MOSI PA7；CS PB2、A0 PA6；参考驱动不操作复位脚 | SPI0：PB8／PB10，CS PB7，A0 PB9，RES PB11 |
| LCD 背光 | PF8；TIM7 + DMA 写 BSRR 做软件 PWM，4 kHz | PB6 |
| BK4829 三线总线 | CS PF9、SCL PB8、SDA PB9 | PC0／PC1／PC2 |
| BK1080 I²C | PF5／PF6（只用于 BK1080） | PA10／PA11，与键盘共用 |
| 键盘列（输出） | PB6、PB5、PB4、PB3 依次为第 0–3 列 | PA10–PA13 |
| 键盘行（输入，上拉） | PB15、PB14、PB13、PB12 依次为第 0–3 行；实测 MENU = PB6／PB15，两侧方向键为 UP（左）／DOWN（右） | PA3–PA6 |
| PTT | PB10，低电平为按下 | PC5 |
| 侧键 | 全部列为高电平时读取行线（零列 → SIDE1／SIDE2） | 同样方法 |
| 音频功放 | PA8 | PC4 |
| 射频状态灯 | BK4829 REG33：bit0 红、bit1 绿；参考映射与用户实机反色现象一致 | BK4819 REG33：bit1 红、bit0 绿 |
| 手电／辅助 LED | PC13 | PC3 |
| 电池 ADC | PB0／PB1 模拟输入，参考固件读 ADC1 CH8 | PA9／PA14 |
| UART（K 型耳机口） | USART1：TX PA9、RX PA10 | UART1：PA7／PA8 |
| USB | MCU 自带 USB 全速，参考固件用 CherryUSB 实现 CDC | 无 |
| SWD | PA13／PA14（参考固件不启用 SWD 时改作 GPIO） | PB11／PB14 |

键盘逻辑矩阵（MENU/1/4/7、UP/2/5/8、DOWN/3/6/9、EXIT/*/0/F）与 K5 相同，只是端口不同。社区资料称 K1 用机身侧面的方向键代替 K5 正面的上下键；物理键帽布局尚未逐项核对。

## 4. 存储内容与本机备份

原厂 7.02.07 通过 `0x051B` 提供一个 64 KiB 的「兼容 EEPROM」逻辑视图。**它不等于 SPI Flash 的物理地址**：参考固件把逻辑校准区 `0x1E00–0x1FFF` 存放在物理地址 `0x010000`（4 KiB 扇区），读 `0x010000 + 0xC0` 即对应 `0x1EC0`。由于参考固件刷入后直接读取该扇区，可以推断原厂固件也把校准存在那里，但这一点未经本机物理读取证实。

| 逻辑范围 | 内容（本机读取） |
| --- | --- |
| `0x0000–0x00FF`、`0x0C80–0x0D5F` | 频道／VFO 频率记录（K5 格式，16 B 一条） |
| `0x0D60–0x0E2F` | 频道属性 |
| `0x0E70–0x0F4F` | 设置，含 `Quansheng` / `UV-K1` 开机字串、DTMF 等 |
| `0x0F50–0x10FF` | 频道名称 `CH001…` |
| `0x1C00–0x1C4F` | DTMF 联系人 `CALL1…` |
| **`0x1E00–0x1FFF`** | **原厂校准** |
| `0x2E00–0x31FF`、`0x3000–0x33FF` | 两份 `5A 5A BC 9A` 头加 128×64 位图，推测为开机画面 |
| 其余 | 全 `0xFF` |

### 校准数据要点（逻辑地址，布局同 UV-K5）

| 地址 | 本机值 | 说明 |
| --- | --- | --- |
| `0x1EC0` | `6E 00 78 00 82 00 8C 00 / B4 00 BE 00 C8 00 D2 00` | RSSI 门限（两组 4 × u16） |
| `0x1ED0 + band × 16` | band 0／1／3／6：`32 32 32 · 64 64 64 · 8C 8C 8C`；**band 2：`5F 5F 5F · 69 69 69 · 91 96 91`**；band 4：`5A 5A 5A · 64 64 64 · 96 96 96`；**band 5：`5A 5A 5A · 64 64 64 · 91 96 91`** | PA 偏置 L／M／H 三锚点 |
| `0x1F40` | 1442、2010、2163、2193、2314、2600 | 电池电压校准（u16） |
| `0x1F88` | 晶振 −2、`0x0046`、`0x0050`、音量增益 44、DAC 增益 14 | 杂项 |

K1 的 band 2／5 High 档（`91 96 91`）与本项目 `tools/resources.py` 中按 UV-K5(8) 推出的参考值（`7A 8B 7F`、`7B 7B 7A`）不同，说明功放链路有差异。**UV-K5／K6 的 PA 参考值不能用于 K1。**

## 5. 当前项目适配状态

`make BOARD=uvk1` 已可构建 PY32F071 首启只读版本（应用起点 `0x08002800`、118 KiB Flash、16 KiB RAM）。`src/boards/uvk1/` 提供引脚默认状态、GPIO、PF8 背光 PWM（TIM7 + DMA7，4 kHz，0–15 档）、PF5/PF6 软件 I²C、电池 ADC 和 SPI Flash 存储；SWD 保留。共享 ST7565、键盘和上层 UI 通过 HAL 访问硬件。

- TX 已接通 BK4829 NFM 路径，默认随共享构建使用 `ENABLE_TX=1`；每槽 TX Enable 默认 Off。功率读取本机原厂 PA 记录；`ENABLE_TX=0` 仍生成仅接收镜像。代码、回归和实机测量边界见 [K1 发射核对](uvk1-tx-audit.md)。
- `drivers/py25q16/` 实现 JEDEC ID、状态、读取、写使能、4 KiB 扇区擦除（`0x20`）与按 256 B 页拆分的页编程（`0x02`）。哪些地址可写由板级决定，驱动不限制。
- 接受本机实测 JEDEC ID `EB 60 15`，以及参考型号 ID `85 60 15`，容量均为 2 MiB；未知 ID 不开放读取窗口，UART `info` 仍报告 ID 便于定位。首刷版本因白名单只含后者显示 Storage unknown，修正版已加入本机 ID。
- 最新离线构建增加 K1 无 SI4732 的板级能力约束，禁止 SI 探测和运行请求；首启电池诊断读取原厂 ADC 校准第 4 点。这些后续改动未刷入、未实测。
- 存储布局（物理地址，每个区独占整扇区）：

  | 区 | 地址 | 说明 |
  | --- | --- | --- |
  | 校准（只读） | `0x010000`，512 B | 原厂；固件和 PC 工具都不擦写 |
  | CONFIG_A／B | `0x020000`、`0x030000`，各 16 扇区 | 轮转日志，每扇区 2 个位置；先写 1 KiB 记录，最后写 8 B 头（计数、反码），开机取计数最大的有效位置。进入新扇区才擦除，当前位置所在扇区永不擦除 |
  | CHANNELS_A／B | `0x040000`、`0x044000`，各 4 扇区 | 200 条 64 B 记录。只需清位（删除、写空白处）时原地编程，否则经日志整扇区改写 |
  | 日志 | `0x048000`（数据）、`0x049000`（头） | 先写新扇区内容，再写头（魔数、目标、CRC32），改写完成后擦头；开机发现有效头即重放 |

- 擦除与编程只允许落在 `0x020000–0x049FFF`；该范围在部分整片读取（`0x000000–0x0ACFFF`）中全部为擦除状态，与原厂及参考固件使用的 `0x000000–0x01FFFF` 不重叠。芯片块保护位非零时不写状态寄存器，整片保持只读，回退到 RAM 配置。
- BK4829 AM 已开放：按参考 RADIO_SetModulation 写入原厂 AM 解调值（`31` bit0、`42=6F5C`、`2A=7434`）、关闭 AFC，AGC 与 FM 相同；6k／12k 使用原厂 AM 滤波预设 `0x345C`，26k 使用 `0x3028`。尚未实机收听验证。
- 静噪开／关延时可调，默认 Auto 采用原厂与参考固件的 5／3。2026-10-19 用户实测旧默认 1／1 接收正常、不跳；早先的「静噪一直跳」发生在接收初始化漏调期间（见 [K1 接收链路核对](uvk1-rx-audit.md)），不能归因于延时过短。
- 首次刷入后没有有效配置，开机进入初始化页，按 0、1 确认后才写入，与 K6 相同。维护写入（PC 工具写校准／资源）在 K1 上仍然拒绝。
- 主机回归在 SPI 级 NOR 模型上运行真实驱动、板级存储、配置与频道存储：逐步注入擦除／编程中途断电，重启后配置和频道只会是旧值或新值，同扇区其他频道不受影响，`0x020000–0x049FFF` 之外的字节（含校准）不变。
- UART `0x0572`/`0x0573` 返回物理容量和存储名（包含 SPI JEDEC ID）；`0x051B`/`0x051C` 使用 32 位物理地址，可以导出完整 2 MiB。
- `tools/flash.py --board uvk1` 校验 K1 向量表并要求 Bootloader 7.x，按参考 `_prog.py` 使用四字节版本握手、16 位小端页号/页数（最多 472 页）。K6 保留实测握手且要求 3.x。K1 跳过 K6 打包，直接输出 raw binary。

首次实机流程和备份命令见 [UV-K1 首启与只读备份](uvk1-bringup.md)。原先规定「两次完整读取并核对一致前不实现外部 Flash 写入」；2026-10-19 用户决定不等整片双读、直接开放写入。当时整片只读到 `0x0ACFFF`，写入范围因此限定在已确认为空白的扇区内。

2026-10-20 经 USB 完成整片 2 MiB 两次读取（`backups/uvk1/uvk1-spi-2MiB-usb-read{1,2}.bin`，各约 7–9 分钟，SHA-256 记入 `SHA256SUMS`）。两次之间设置保存过一次，唯一差异是 CONFIG_B 日志位置 31（`0x03F800–0x03FC04`，1 KiB 记录加头）；`0x020000–0x049FFF` 以外逐字节一致，校准扇区与原有备份一致。整片占用：

| 范围 | 内容 |
| --- | --- |
| `0x000000–0x011FFF` | 原厂频道／设置、`0x010000` 校准、开机图（中间有空白扇区） |
| `0x012000–0x01FFFF` | 空白 |
| `0x020000–0x044FFF` | 本固件的配置日志与频道 |
| `0x045000–0x0FFFFF` | 空白 |
| `0x100000–0x1E2FFF` | 原厂数据约 908 KiB（内容未解析，疑为字库或图片资源），此前从未备份 |
| `0x1E3000–0x1FFFFF` | 空白 |

- USB CDC：`drivers/py32f071/usb.c` 是本项目自写的精简 CDC-ACM 设备驱动（寄存器按 Puya 的 CherryUSB 移植层），时钟沿用 Bootloader 留下的 48 MHz HSI。VID:PID 为 pid.codes 测试号 `1209:0001`，厂商／产品字串 `uvk6-reborn`／`UV-K1 Reborn`，序列号取芯片 UID，不冒用原厂 `36B7:0001`「K1 CPS」。PC 链路协议与 K 头 UART 相同，回复走请求所在的线路；主机未打开端口（DTR）时输出直接丢弃，不阻塞主循环。K 头线通信后 5 秒内按键暂停（K 头线同时是麦克风、耳机与 PTT 线路，防止误触发和通信中发射）；USB 通信不暂停按键。刷机仍须走 K 头线（Bootloader 只认 UART）。
- 2026-10-20 实机：macOS 枚举为 `/dev/cu.usbmodem7262025C1`；经 USB 的 `info`、`stats`、`rf` 正常，64 KiB 读取 13.8 s（约 4.7 KB/s，受每次 128 B 的请求往返限制），其中校准扇区与备份逐字节一致。

后续工作：K1 能力/菜单适配。

2026-10-19 刷入 `3990ae8` 后实机验收：首次开机进入初始化页并确认，设置、频率和频道保存、覆盖、删除在重启后均按预期保留。断电中途恢复只有主机回归覆盖，未在实机上拔电测试。BK4829／BK1080 两路接收及切换已有实机听音确认。TX 校准已接通，当前进入实机验收阶段；功率、频偏和杂散尚未测量，不能使用 K6 PA 参考值。
