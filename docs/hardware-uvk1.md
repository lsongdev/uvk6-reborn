# UV-K1 硬件事实

更新于 2026-10-20。泉盛 UV-K1「MiniKong」是同仓库第二目标，主开发基线仍是 [UV-K6 512 大内存版](hardware-uvk6.md)。本文区分三类证据：**本机实测**（经 USB 只读读取）、**参考固件源码**（他人移植固件中的接线，未经本机 PCB 测量）和**厂家／社区资料**。

芯片原始手册：[BK4829 E01 V1.0](datasheets/BK4829.pdf)，标称收发 18–580／760–1160 MHz；固件保留更宽调谐范围，见[范围与 PA 选择规则](design.md#板级范围与-pa-数据)。

### Bootloader（2026-10-19，只监听）

K1 按住 PTT 开机进入刷机模式后，经 **K 头 UART 线**（38400 baud）持续广播 `0x0518`，帧格式与 UV-K5/K6 相同（XOR 混淆、CRC16）。本次只接收，未回复 `0x0530` 握手，也未发送任何数据。

| 字段 | 值 |
| --- | --- |
| Bootloader 版本 | **7.02.02**（UV-K6 为 3.00.02） |

参考固件的刷写工具（`tools/serialtool/_prog.py`）使用同一流程：收到 `0x0518` 后回 `0x0530`（Bootloader 版本），再以 `0x0519` 按 256 B 页写入，`0x051A` 应答。两种机型的 Bootloader 版本号前缀不同（3.x／7.x），刷写工具据此识别板型，避免把一种机型的镜像刷进另一种：参考项目记录了把 K1 镜像刷进 UV-K5 V1 后只能拆机经 SWD 恢复的案例。

## 2. MCU 与存储（参考固件源码）

主要依据：[armel/uv-k1-k5v3-firmware-custom](https://github.com/armel/uv-k1-k5v3-firmware-custom)（commit `5fedc09`，2026-10-17），即 F4HWN 的 UV-K1／UV-K5 V3 移植版；其 README 说明这两款机型改用 PY32F071。尚未通过本机芯片丝印核实。

| 项目 | UV-K1 | 本项目 UV-K6 基线 |
| --- | --- | --- |
| MCU | **Puya PY32F071xB**（Cortex-M0+） | DP32G030（Cortex-M0） |
| 内部 Flash | 128 KiB；Bootloader 占 `0x08000000–0x080027FF`（10 KiB），应用从 **`0x08002800`** 起，可用 **118 KiB** | 应用 60 KiB，从 `0x00000000` 起 |
| RAM | 16 KiB（`0x20000000`） | 16 KiB |
| 时钟 | 参考固件按 48 MHz 运行，HSE 宏为 24 MHz | DP32G030 平台配置 |
| 向量表 | 应用设置 `SCB->VTOR`（M0+ 支持） | 位于 0 地址 |
| 外部存储 | **2 MiB SPI NOR Flash，本机 JEDEC ID `EB 60 15`（2026-10-19 自编固件实测）；参考驱动名 PY25Q16**，扇区擦除 4 KiB，页编程 256 B；SPI2：SCK PA0、MOSI PA1、MISO PA2，CS PA3 | I²C EEPROM 512 KiB |
| 射频芯片 | 参考固件只编译 `bk4829.c`，即 **BK4829**（BK4819 的后续型号，寄存器大体相同但有差异） | BK4819 |

社区站点 [uv-k1.com](https://uv-k1.com/) 也说明换用了新处理器，UV-K5 固件不兼容；并提到 UV-K1(8) 有一个带 8 MB Flash 的型号。本机后续用自编只读固件读取 `0x9F`，返回 `EB 60 15`，与 2 MiB 容量相符；芯片厂商/丝印尚未确认，不能仅凭参考驱动名认定为 Puya。

## 4. 存储内容与本机备份

原厂 7.02.07 通过 `0x051B` 提供一个 64 KiB 的「兼容 EEPROM」逻辑视图。**它不等于 SPI Flash 的物理地址**：参考固件把逻辑校准区 `0x1E00–0x1FFF` 存放在物理地址 `0x010000`（4 KiB 扇区），读 `0x010000 + 0xC0` 即对应 `0x1EC0`。2026-10-19 自编固件按物理地址读取该区，2026-10-20 整片 USB 备份再次核对，均与原厂逻辑校准备份逐字节一致。其余逻辑地址的完整映射仍未解析。

| 逻辑范围 | 内容（本机读取） |
| --- | --- |
| `0x0000–0x00FF`、`0x0C80–0x0D5F` | 频道／VFO 频率记录（K5 格式，16 B 一条） |
| `0x0D60–0x0E2F` | 频道属性 |
| `0x0E70–0x0F4F` | 设置，含 `Quansheng` / `UV-K1` 开机字串、DTMF 等 |
| `0x0F50–0x10FF` | 频道名称 `CH001…` |
| `0x1C00–0x1C4F` | DTMF 联系人 `CALL1…` |
| **`0x1E00–0x1FFF`** | **原厂校准** |
| `0x2E00–0x31FF`、`0x3000–0x33FF` | 两份 `5A 5A BC 9A` 头加 128×64 位图，推测为开机画面 |
| 其余 | 全 `0xFF` |

### 校准数据要点（逻辑地址，布局同 UV-K5）

| 地址 | 本机值 | 说明 |
| --- | --- | --- |
| `0x1EC0` | `6E 00 78 00 82 00 8C 00 / B4 00 BE 00 C8 00 D2 00` | RSSI 门限（两组 4 × u16） |
| `0x1ED0 + band × 16` | band 0／1／3／6：`32 32 32 · 64 64 64 · 8C 8C 8C`；**band 2：`5F 5F 5F · 69 69 69 · 91 96 91`**；band 4：`5A 5A 5A · 64 64 64 · 96 96 96`；**band 5：`5A 5A 5A · 64 64 64 · 91 96 91`** | PA 偏置 L／M／H 三锚点 |
| `0x1F40` | 1442、2010、2163、2193、2314、2600 | 电池电压校准（u16） |
| `0x1F88` | 晶振 −2、`0x0046`、`0x0050`、音量增益 44、DAC 增益 14 | 杂项 |

K1 的 band 2／5 High 档（`91 96 91`）与本项目 `tools/resources.py` 中按 UV-K5(8) 推出的参考值（`7A 8B 7F`、`7B 7B 7A`）不同，说明功放链路有差异。**UV-K5／K6 的 PA 参考值不能用于 K1。**

## 5. 当前板级实现与存储保护

`make BOARD=uvk1` 构建应用起点 `0x08002800`、118 KiB Flash、16 KiB RAM 的镜像。板级提供引脚、GPIO、PF8 背光 PWM（TIM7＋DMA7，4 kHz，0–15 档）、PF5/PF6 软件 I²C、电池 ADC、SPI 存储和 LED 映射，SWD 保留。共享 UI、射频和存储逻辑通过 HAL 使用本板。首启只读诊断版本已被正常收发和持久化实现取代。

外部 Flash 接受本机 `EB6015` 和参考 `856015` 两个 JEDEC ID，均按 2 MiB；未知 ID 不开放读取窗口，`info` 仍报告 ID。不能用参考驱动名断定实际厂商。芯片块保护位非零时不改状态寄存器，保持只读并回退 RAM 配置。没有有效 UVR2 格式 9 时，用户先按 0、1 确认初始化，才开放正常配置写入。

### 物理地址与擦写边界

| 区域 | 物理范围 | 处理 |
| --- | --- | --- |
| 原厂校准扇区 | **`0x010000–0x010FFF`**（前 512 B 为已知校准） | **绝不擦写**；固件和 PC 维护工具均无写入路径 |
| CONFIG_A | `0x020000–0x02FFFF` | 16 个扇区的轮转日志 |
| CONFIG_B | `0x030000–0x03FFFF` | 独立第二份配置日志 |
| CHANNELS_A | `0x040000–0x043FFF` | 200 × 64 B，区尾为扇区对齐余量 |
| CHANNELS_B | `0x044000–0x047FFF` | 频道镜像，独立擦除区域 |
| 改写日志数据／头 | `0x048000–0x048FFF`／`0x049000–0x049FFF` | 整扇区改写与启动重放 |

唯一允许编程／擦除的物理范围仍是 **`0x020000–0x049FFF`**。完成整片备份不自动扩大写入范围；新增范围须先读出并确认目标扇区空白。PC 的校准和资源维护写在 K1 全部拒绝。

配置日志每个 4 KiB 扇区放两个 2 KiB 位置；先写 1 KiB UVR2 记录，最后写 8 B 计数／反码头，启动取最新有效位置。进入新扇区才擦除，不擦当前位置扇区。频道仅清位时原地编程，否则先写日志数据和带目标／CRC 的头，再改写目标，完成后擦日志头；启动重放有效未完成日志。每条频道的两份位于不同区域，写旧份后镜像，避免整扇区重写使同扇区其他记录回滚。实现见 [storage.c](../src/boards/uvk1/storage.c)、[storage-layout.h](../src/boards/uvk1/storage-layout.h)。

### USB 与 UART

`drivers/py32f071/usb.c` 为本项目精简 CDC-ACM 驱动，寄存器依据 Puya 的 CherryUSB 移植层，沿用 Bootloader 留下的 48 MHz HSI。自编应用使用 pid.codes 测试号 **`1209:0001`**，字串 `uvk6-reborn`／`UV-K1 Reborn`，序列号取芯片 UID；与 §1 原厂 `36B7:0001` 枚举分别记录。

PC 协议经 `hal/serial.h` 统一承载，回复回到请求线路；未打开 USB 端口（DTR）时丢弃输出，不阻塞主循环。USB 通信不暂停按键；K 头 UART 通信后 5 秒暂停按键，避免共享麦克风／耳机／PTT 线路误触。**Bootloader 仍只认 K 头 UART，USB 仅用于运行中的应用。**

实机 USB `info`、`stats`、`rf` 成功；64 KiB 读取 13.8 s，约 4.7 KB/s，受每次 128 B 请求往返限制，校准内容与备份一致。

## 6. 接收、发射与实机证据

### 校准数据与频率锚点

七段 PA 记录相对校准区偏移为 `0xD0 + band × 16`，每档 Low／Medium／High 各三个值；本板物理地址为 `0x010000 + 偏移`。按实际 TX Hz 选择，端点钳位和无效数据规则见[设计文档](design.md#板级范围与-pa-数据)。

| band | 物理记录起点 | 三锚点 MHz |
| --- | --- | --- |
| 0 | `0x0100D0` | 50／63／76 |
| 1 | `0x0100E0` | 108／122.5／137 |
| 2 | `0x0100F0` | 137／155.5／174（136–137 使用最低锚点） |
| 3 | `0x010100` | 174／262／350 |
| 4 | `0x010110` | 350／375／400 |
| 5 | `0x010120` | 400／435／470 |
| 6 | `0x010130` | 470／535／600 |

依据 [F4HWN 5fedc09 原厂频段表](https://github.com/armel/uv-k1-k5v3-firmware-custom/blob/5fedc09e9ddec350823adb9bb2d81df05b52ab8d/App/frequencies.c) 的非 WIDE_RX 分支。七段均有非零本机记录，不复制功率提升增量。调谐范围为 18–660／760–1300 MHz（含端点），其中 580–660 和 1160–1300 MHz 超出手册标称范围，尚无 RF 测量结论。

### BK4829 与 K6 的实现差异

参考 [F4HWN 5fedc09e](https://github.com/armel/uv-k1-k5v3-firmware-custom/tree/5fedc09e9ddec350823adb9bb2d81df05b52ab8d/App) 与 [ApeX 41cc768d](https://github.com/N7SIX/UV-K1Series_ApeX-Edition_v7.6.0/tree/41cc768d946bff97db691ee372b4dbf9bc46743e/App)。两者代码谱系相近，交叉核对不等于独立硬件验证。

| 链路 | K1 当前实现与证据 |
| --- | --- |
| 启动 | `RADIO_Init → RECEIVER_Init → RX_DEVICE_Init → BK48X9_Init`，初始化幂等；旧版本漏调初始化已修复 |
| RX 电源／调谐 | REG37 初始 `9D1F`、RX `9F1F`；REG30 `0000 → BFF1`，调谐重启也先清零，保留扫描 DAC 状态 |
| 参考时钟／音频校准 | trim −2 → REG3B `587E`；AF／DAC 原厂 44／14，REG48 `B2CE`，FM DAC 设 15 后 `B2CF`；不覆盖 K6 REG3C |
| FM／AGC | REG31 bit0=0；42=`6B5A`、2A=`7400`、2B=0、2F=`9890`、54=`9009`、55=`31A9`；AGC 10–14=`0318/033A/03DB/03DF/0210`、49=`2AB2`、7B=`73DC`、7E=`303E` |
| 滤波 | FM 6k／12k／26k 标签对应 `2058/4048/3028`，为名义标签，非实测 −3 dB 带宽 |
| AM | 31 bit0、42=`6F5C`、2A=`7434`，关闭 AFC；6k／12k=`345C`、26k=`3028`；已实现，未做本机听音确认 |
| 静噪 | 174 MHz 以下校准偏移 `0x60`，以上 `0x00`；六行阈值转换；快速调频跨界重选表，调谐前清旧事件。Auto 开／关为 5／3；SQ0 绕过载波状态，仍受 RX Tone 限制 |
| 音频门控 | 正常静噪关门保留 DAC，AF 开／关 `6142/6042`；先关功放再关音频。后台准备和跨芯片路由可关闭 DAC |
| 亚音 | CTCSS REG51=`9040`，换算 2.06488；DCS=`A033`、控制字 2775；共用标准码表 |
| TX | REG50 静音／开麦 `BB18/3B18`，REG37=`9D1F`、REG52=`028F`、REG30=`0000 → C1FE`；REG43=`4048`、REG40=`3516`；共享 Deviation 字段只作用于 BK4819 |
| 麦克风／恢复 | REG19=`1041`、REG7D=`E940 OR mic`，不写 K6 的 REG74；REG7E 仅改位 5:3 为 5，REG2B=0；松键先关 PA、REG36 清零，失效缓存并完整恢复 RX |
| 指示灯 | REG33 bit0 红／bit1 绿，由板级定义；共享语义为 TX 红、RX 开音频绿 |

发射前 `RX_DEVICE_StopAll` 必须成功，BK1080 待机失败时不准备 TX DSP、不开放 PA。TX 默认编译，槽级默认 Off；仅接收变体仍可构建。NFM、广播切换与共享前端约束见[设计文档](design.md#4-多-slot-守听与音频归属)。

## 7. 尚待确认

- 芯片丝印与 PCB 通断测量；2 MiB 容量和当前板级开发基线已确认，不因丝印待补而重新询问型号／容量。
