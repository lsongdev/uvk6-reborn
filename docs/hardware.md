# UVK6 Reborn 硬件事实

本文汇总厂家数据手册和固件源码中的硬件信息。芯片规格不代表整机已安装对应芯片，也不代表整机性能已验证。

## 当前开发设备与固定硬件基线

**自 2026-10-12 起，本项目当前开发设备固定为泉盛官方绿色 UV-K6「512 大内存」版本，EEPROM 容量按 4 Mbit = 524,288 B = 512 KiB 使用。** 这是用户明确确认的开发目标，后续设计、实现与容量预算直接沿用，不再要求用户重复核实设备型号或 EEPROM 容量，也不再默认本机是普通 8 KiB 版本。

| 项目 | 当前开发基线 |
| --- | --- |
| 整机型号 / 版本 | 泉盛 UV-K6，官方绿色 512 大内存版 |
| 外部 EEPROM 总容量 | **512 KiB（4 Mbit）**；不是 512 Kbit，也不是 MCU 内部 Flash |
| MCU 开发平台 | DP32G030 / ARM Cortex-M0，使用现有平台代码与工具链 |
| 应用 Flash 预算 | **60 KiB**，按当前链接脚本 |
| RAM 预算 | **16 KiB**，按当前链接脚本 |
| Bootloader | **3.00.02**，本机串口已读取 |

下文对芯片丝印、数量、页大小及接线的实测状态说明，只用于区分证据来源，不撤销上述开发基线，也不构成再次向用户询问型号或容量的前置条件。若实现需要更细的器件参数，优先检查源码、资料或自动探测；只有实际证据与基线冲突，或用户明确更换设备时，才修订此记录。

## MCU 与固件内存布局：源码定义

项目面向 DP32G030 平台，构建参数为 ARM Cortex-M0、Thumb、AAPCS。寄存器定义位于 `src/drivers/dp32g030/`。尚未通过本台设备芯片丝印独立确认 MCU 型号。

[链接脚本](../firmware.ld) 定义：

| 区域 | 起始地址 | 固件允许使用的大小 |
| --- | --- | --- |
| 应用 Flash | `0x00000000` | 60 KiB |
| RAM | `0x20000000` | 16 KiB |
| 栈顶 | `0x20004000` | RAM 末尾 |

这些是构建约束，不能据此推断整片 Flash 容量和 Bootloader 的实际地址。2026-10-12 紧凑 VFO + RDS + F1/F0 快捷键版本编译报告 Flash 使用 42,028 B、RAM 使用 4,656 B；RAM 数字包括链接时预留部分，不是运行时堆栈峰值测量。

## 外设与 GPIO：源码定义

主要依据：[GPIO 名称](../src/hal/gpio.h)、[引脚复用初始化](../src/hal/board.c)、[键盘扫描](../src/hal/keyboard.c)。下表为固件预期映射，未经本台 PCB 通断测量。

| 功能 | MCU 引脚 | 备注 |
| --- | --- | --- |
| UART1 TX / RX | PA7 / PA8 | 刷机及应用串口所用配置 |
| I²C SCL / SDA | PA10 / PA11 | 软件 I²C，与键盘扫描输出行共用 |
| 键盘扫描输入 | PA3、PA4、PA5、PA6 | 对应四列输入 |
| 键盘扫描输出 | PA10、PA11、PA12、PA13 | PA12 / PA13 还被命名为语音芯片引脚 |
| PTT | PC5 | 按下读取为低电平 |
| LCD 背光 | PB6 | GPIO 控制；亮度实现见背光驱动 |
| LCD SPI 片选 / 时钟 / 数据 | PB7 / PB8 / PB10 | SPI0 的 SSN / CLK / MOSI |
| LCD A0 / 复位 | PB9 / PB11 | 驱动面向 ST7565，画面尺寸定义为 128×64 |
| SWD 数据 / 时钟 | PB11 / PB14 | PB11 与 LCD 复位复用 |
| BK4819 控制总线 | PC0 / PC1 / PC2 | SCN / SCL / SDA，区别于 PA10 / PA11 的 I²C |
| 辅助 LED（原手电筒位置） | PC3 | 用户已改为 LED，`hal/led` 提供 GPIO 控制接口 |
| 音频路径控制 | PC4 | 接收音频路由 |
| BK1080 控制 | PB15 | 某些改装接收路径也使用相关控制逻辑 |
| 电池 ADC | PA9 / PA14 | 配置为 ADC CH4 / CH9，代码分别读取为电压 / 电流原始值 |

红、绿指示灯通过 BK4819 的 GPIO 控制，代码分别使用 `BK4819_GPIO5_PIN1_RED` 和 `BK4819_GPIO0_PIN28_GREEN`，不是上表 MCU 的直接 GPIO。指示灯状态受外设初始化及 Bootloader 行为影响。

由于键盘与 I²C 共用 PA10 / PA11，键盘轮询会改变这些引脚的输出状态。维护驱动时必须一起检查 GPIO 方向、输入使能、开漏配置及总线空闲状态。

## 键盘、键帽标记与快捷键设计依据

按键编号与扫描位置依据 [按键枚举](../src/hal/keyboard.h)、[键盘矩阵](../src/hal/keyboard.c) 和 [GPIO 定义](../src/hal/gpio.h)。键帽主标、副标是物理标记，不等同于当前固件已经绑定的功能；当前短按、长按行为以 [用户手册](user-manual.md#主界面与按键) 为准。

**键帽依据**：2026-10-12 逐项核对[泉盛官方 UV-K5(8) 产品页](https://en.qsfj.com/products/3268)的清晰正面图（图片文件 `fm-1683793427.png`）。厂家该页面正文称设备为 UV-K6，[对应下载页](https://en.qsfj.com/support/downloads/3268)也包含 UV-K6 资料。`M(A)`、`▲(B)`、`▼(C)`、`1(Band)`、`2(A/B)` 同时与用户提供的本台标记一致。下表完整记录厂家图中的主标与副标；大小写保留键帽写法，换行副标以 `/` 连写。它是原厂面板依据，换装键帽时应同步更新。

### 正面按键

| 主标（副标） | 固件按键 / 编号 | 标记含义与后续设计参考 |
| --- | --- | --- |

| `1(Band)` | `KEY_1` / 1 | 频段选择或切换 |
| `2(A/B)` | `KEY_2` / 2 | A/B VFO 选择或切换 |
| `3(VFO/MR)` | `KEY_3` / 3 | 频率模式 / 存储频道模式切换 |
| `4(FC)` | `KEY_4` / 4 | 频率捕获 / 复制；厂家称 Fast Copy One Channel |

| `6(H/M/L)` | `KEY_6` / 6 | 高 / 中 / 低发射功率 |

| `F(# / 钥匙图标)` | `KEY_F` / 15 | 主标为 F，副标为 `#` 和钥匙图标；对应功能组合、DTMF `#` 与键盘锁语义 |

面板位置参考（从上到下、从左到右；括号内为副标）：

```text
M(A)
▲(B)          [扬声器]
▼(C)          [扬声器]
EXIT(D)
1(Band)       2(A/B)        3(VFO/MR)     *(Scan)
```

`A/B` 的 VFO 选择标记与菜单、方向、退出键上的 DTMF `A/B/C/D` 是两套含义；后续设计应明确区分。表中 NOAA、功率、VOX、倒频、频道、扫描等标记只记录硬件操作语义，不表示当前单 VFO 固件已提供这些功能。

下表是电气扫描关系，不是面板的排布方向。每次将一条输出线拉低，再读取四条输入线；按下时输入为低电平。

| 拉低的输出线 | PA3 输入 | PA4 输入 | PA5 输入 | PA6 输入 |
| --- | --- | --- | --- | --- |
| PA10 | `M` / `KEY_MENU` | `1` | `4` | `7` |
| PA11 | `▲` / `KEY_UP` | `2` | `5` | `8` |
| PA12 | `▼` / `KEY_DOWN` | `3` | `6` | `9` |
| PA13 | `EXIT` / `KEY_EXIT` | `*` / `KEY_STAR` | `0` | `F`（副标 `#`）/ `KEY_F` |

| 侧面按键 | 固件按键 / 编号 | 源码读取方式 |
| --- | --- | --- |
| PTT | `KEY_PTT` / 21 | PC5 独立读取，按下为低电平 |
| 侧键 1 | `KEY_SIDE1` / 23 | 全部矩阵输出线置高时读取 PA3，按下为低电平 |

键盘扫描表中的零行多次列出侧键 2，是同一输入的重复表项，不表示存在更多侧键。按键事件定义包括按下、释放、长按和长按连续事件；当前长按门限为 **500 ms**，连续事件间隔为 **100 ms**。矩阵扫描一次返回一个按键，PTT 独立轮询；组合键能力不能仅由这些定义推断。

### 后续快捷键绑定约定

- 优先遵循键帽标记，例如 `1(Band)` 对应频段操作，`2(A/B)` 对应 VFO 选择，`0(FM)` 在本项目中对应解调模式，`*(Scan)` 对应扫描，`F` 的钥匙图标对应键盘锁。
- 数字键短按继续承担频率／数值输入。副标快捷键统一使用短按 `F → 目标键` 的顺序操作，数字键不增加长按副标入口；详见[设计中的统一绑定规则](design.md#33-f-前缀与副标快捷键统一绑定规则)。长按 F 专用于键盘锁。
- `M`、方向键和 `EXIT` 在菜单与输入界面优先承担确认、导航和取消，不被全局快捷键覆盖。
- 尚未实现的副标功能提示暂未支持，不绑定成无关操作。当前侧键 1 切频段、侧键 2 切模式的绑定保留，后续在设置中支持修改侧键功能。

## BK4819 与 SI4732：厂家资料

以下依据 BK4819 和 SI4732-A10 的厂家公开资料，独立于本项目的频率常量、菜单和驱动实现。

| 芯片 | 厂家列出的工作频段 | 主要用途与能力 |
| --- | --- | --- |
| BK4819 | 18–660 MHz、840–1300 MHz | 半双工 FM 收发；面向窄带对讲语音，支持 6.25 / 12.5 / 20 / 25 kHz 信道间隔、CTCSS / DCS、DTMF 和 FSK 等 |
| SI4732-A10 | LW 153–279 kHz；MW 520–1710 kHz；SW 2.3–26.1 MHz；FM 64–108 MHz | 广播接收；AM 与广播 FM，支持 FM 立体声、RDS / RBDS 和可选 AM 通道滤波器；不提供发射 |

来源：[Beken BK4819 数据手册](https://offer-product.oss-cn-beijing.aliyuncs.com/product/offer/attachment/2216999951400/file/subPdf_729460_326293_20231219-105353923.pdf)、[Skyworks SI4732-A10 数据手册](https://www.skyworksinc.com/-/media/Skyworks/SL/documents/public/data-shorts/Si4732-A10-short.pdf)。BK 的信道间隔不等同于接收滤波器带宽；SI 的广播频段列表也不表示从长波到 108 MHz 连续覆盖。

### 频率交集与模式区别

按上表标称频段取交集，重叠位置是 **18–26.1 MHz** 和 **64–108 MHz**：

- 18–26.1 MHz：SI 的标称用途是短波 AM 接收；BK 的标准用途是 FM 通信。频率交集不表示支持同一种解调模式。
- 64–108 MHz：SI 面向宽带 FM 广播（WFM），包括立体声和 RDS；BK 面向窄带 FM 对讲（NFM）。BK 能调到广播载频，或听到部分失真声音，不足以证明能正确接收 WFM 广播。
- 145 MHz 和 430 MHz 均在 BK 的标称工作范围内，超出 SI 的标称接收频段；SI 不能直接接收这些常见对讲机频率。

路由规则：**频率与用户明确选择的模式共同决定接收芯片**。例如 100 MHz + NFM 走 BK4819，100 MHz + WFM 走 SI4732；20 MHz + NFM 走 BK4819，20 MHz + AM / 补丁支持的 LSB/USB 走 SI4732。仅凭频率重叠不能替换用户选择的模式。

**TX 单独决策**：选择 NFM/BK4819 只表明存在硬件发射候选，绝不自动授予发射资格。WFM/SI4732、广播 BK1080 和 AM/SSB 接收不提供自动 TX 兜底。当前固件未完成整机功放与发射频段验证，因此全部 TX 均禁用；后续必须按频率、模式、用户授权、整机 TX 白名单及安全状态共同校验。

本文中的 NFM 指对讲机窄带 FM，WFM 指广播宽带 FM。BK 的上述公开手册没有将广播 WFM、AM 或 SSB 列为标准接收能力；固件实现的 AM 或其他扩展模式，应单独记录实现依据和实机验证。SI 的 SSB 补丁能力也须与公开数据手册列出的基础功能分开记录，加载补丁不能据此推断支持 VHF / UHF 对讲频段。

### 芯片标称范围与整机范围

BK 手册没有将 660–840 MHz 列入工作频段。当前新接收规划仅允许 BK 标称 18–660 MHz 和 840–1300 MHz；航空 8.33 kHz 步进按 25 kHz/3 计算真实调谐频率，**频道名称与真实载波频率并非同一字段**，目前界面显示真实频率而非 ICAO 频道名称。固件扩展调谐范围（例如 SI 到 30 MHz、BK 的上下界扩展）不能直接作为厂家保证的工作规格，应注明资料依据及验证状态。

芯片工作范围不等于整机接收效果，也不等于整机可发射范围。接收还受射频前端、滤波器、天线匹配和音频路径影响；BK 发射还取决于整机功放、输出滤波、匹配和校准。两颗芯片的覆盖重叠不能作为自动替换解调模式或扩大整机发射范围的依据。

对应软件设计见[接收路径选择与发射校验](design.md#62-固定选择策略)：按频率、明确模式及设备能力选择接收路径，独立计算发射资格。

## 接收与发射路径：源码定义

固件包含 `BK4819`、`BK1080`、`SI4732` 驱动。驱动存在不代表具体设备安装了对应芯片。BK4819 是固件实现收发操作的主要路径；BK1080 用于广播接收路径；SI4732 路径需要对应硬件。SI4732 的 SSB 接收依赖补丁。菜单出现 `LSB` / `USB` 不代表补丁或硬件已就绪。

## 亚音实现与验证范围

RX Tone 仅适用于 BK4819 的 NFM 路径。CTCSS 使用已有 50 项 Hz×10 表，DCS 使用已有 104 项代码及 Golay 正码／反码编码；驱动配置检测器，并以 FOUND／LOST 中断事件保持匹配状态。音频打开条件为静噪门限满足且亚音匹配，Off 关闭检测；切频前清除旧事件与匹配状态，轮询最多处理 8 次，避免硬件异常阻塞主循环。实现参考 [Egzumer 的接收配置](https://github.com/egzumer/uv-k5-firmware-custom/blob/main/radio.c)及[亚音中断处理](https://github.com/egzumer/uv-k5-firmware-custom/blob/main/app/app.c)。

TX Frequency 与 TX Tone 已进入独立发射方案，Same 在规划时解析为 RX 频率，显式 TX Hz 单独进行范围与授权校验。生产 `TX_DEVICE` 仍不提供真实 PA 输出能力。主机回归已覆盖亚音事件、静噪联合判断、切频复位、配置读写和独立 TX 频率；本次尚未用信号源验证本机实际亚音识别或发射波形。

## EEPROM：芯片资料、改装方案与本机确认

以下结论分三层：**厂家数据手册**能确定某一型号的组织方式；**UV-K5/K6 改装项目**能证明某些硬件组合已被使用；**本台设备**的实际丝印、地址脚和存储内容，在实机核查前不能由软件猜测为确定事实。本文不要求兼容旧固件，但不得误写射频校准或 SSB 补丁。

### 已有厂家资料的典型型号

| 型号 / 使用场景 | 物理容量 | 物理页大小 | 总线与寻址 | 写周期 |
| --- | --- | --- | --- | --- |
| **BL24C64A**：原机常见 EEPROM | **64 Kbit = 8,192 B = 8 KiB** | **32 B** | 16 位字地址传输（有效地址 13 位）；A0/A1/A2 为外部器件地址脚 | Belling 所引版本标称不超过 3 ms |
| **M24M02-DR**：扩容改装型号之一 | **2 Mbit = 262,144 B = 256 KiB** | **256 B** | 18 位阵列地址；高位通过 I²C 器件选择码、低 16 位通过两字节字地址发送 | **最多 10 ms** |
| **BL24CM2A**：另一个 2 Mbit 扩容型号 | **2 Mbit = 262,144 B = 256 KiB** | **256 B** | 18 位阵列地址；A2 为物理器件地址选择脚，阵列高位与器件地址共用控制字 | **最多 8 ms** |
| **2 × 2 Mbit**：部分双 EEPROM 改装 | **4 Mbit = 524,288 B = 512 KiB**（总计） | 依照所用芯片，不能仅凭总容量断定 | 需要两颗芯片正确配置器件地址脚并分别寻址 | 依照具体型号 |

**注：位与字节不能混淆。** 原机标记 `24C64` 中的 64 是 64 Kbit，只有 8 KiB；`M24M02` 是 2 Mbit，只有 256 KiB，绝非 2 MiB。原机 24C64 → 2 Mbit 替换以及双芯片扩容，已有改装案例，但不代表所有 UV-K6 V6 扩展板出厂默认配备这些存储器。

- [ST M24M02-DR 厂家说明](https://www.st.com/en/memories/m24m02-dr.html)：256 KiB、256 B 页、最长 10 ms 写入周期、可选独立 256 B 标识页。
- [Belling BL24CM2A 数据手册](https://www.belling.com.cn/media/file_object/bel_product/BL24CM2A/datasheet/BL24CM2A_V1.02_en.pdf)：256 KiB、256 B 页、最长 8 ms 写入周期、高位阵列寻址。
- [ST M24M02-A125 厂家说明](https://www.st.com/en/memories/m24m02-a125.html)：也是 256 KiB、256 B 页，但该不同系列标称最长 5 ms。不能把它的时序当作 M24M02-DR 的时序。

### UV-K5/K6 项目提供的独立证据

- [双 EEPROM 改装板作者的一手记录](https://forum.hamcq.cn/d/1952)（2024-06）：明确记录泉盛已有官方 4 Mbit（512 K Byte）大容量机型，并将其与普通 64 Kbit（8 KiB）机型区分。文章也介绍作者自己的双芯片改装方案；不能据此把官方机型的芯片型号、数量或接线认定为与该改装板相同。
- [UV-K5 HF 改装实例](https://sites.google.com/site/om1aeg/vysiela%C4%8Dky/quansheng-uv-k5-hf-mod)：照片及文字记录原机 BL24C64A 更换为 M24M02，并安装 SI4732 取代广播接收芯片 BK1080；**SI4732 扩展板与 EEPROM 扩容是两个独立硬件变更**。
- [IJV 固件手册](https://www.universirius.com/en/preppers/quansheng-uv-k5-manuale-del-firmware-ijv_v3/)：未改机使用 8 KiB 24C64；大容量频道版本需更换 EEPROM 为 1 Mbit 24M01 等型号。
- [LOSEHU 官方固件 / EEPROM 布局](https://github.com/losehu/uv-k5-firmware-custom/blob/main/README.md)：明确区分普通版、1 Mbit / 2 Mbit 扩容版及 SI4732 支持。该项目的 **2 Mbit 布局**记录 SSB patch 位于 `0x3C228–0x3FFFF`（约 15,832 B）；该长度和本项目的 Hawk5 8,840 B patch **不是同一个文件格式或布局约定**。
- [LOSEHU 多固件 Bootloader 项目](https://github.com/losehu/uv-k5-bootloader-custom)：还使用多个 EEPROM 和额外存储区域；因此其他人的高地址内容不能直接复用于本机。

| Bootloader | **3.00.02** | 从 `/dev/cu.usbserial-1420` 接收到 Bootloader hello，38400 baud；本次只接收握手，没有发起固件刷写或 EEPROM 写入 |
| 物理 EEPROM | 型号、数量、页大小及地址脚连接待确认 | 512 KiB 总容量不能确定是单颗器件还是双芯片，也不能确定物理页大小 |

后续应以 **512 KiB 标称 EEPROM 版本**作为本机设计背景，不再把普通机型的 8 KiB 当成本机已确认事实。Bootloader hello 没有提供 EEPROM 型号或容量字段；要进一步验证，需要运行支持读取的固件，记录 I²C 应答、读取各 bank 的内容并核对地址映射。相同内容或全 `0xFF` 不能单独证明地址回绕或真实容量；完整物理型号仍以芯片丝印和相应数据手册为依据。

这使外部中文字库成为可行的设计方向：此前分析的叮咚鸡 12×12 字形与 Unicode 索引约 185 KiB，加入拼音数据约 201 KiB，均小于标称 512 KiB。这里只判断容量可容纳；还需确认本机已有校准、SSB patch 和其他资源的布局，设计本项目的字体读取、UTF-8 解码、缓存及资源写入工具。不能直接照搬叮咚鸡的 SPI Flash 地址或驱动到本机 I²C EEPROM。

### 地址字、应答探测与页写约束

对以上示例的 **2 Mbit EEPROM**，常规数据区需要 18 位地址：最低 16 位是 I²C 字地址两个字节，另外 2 位作为器件地址字的 bank 选择位。对于 **A2=0 的 BL24CM2A 类电路**，128–512 KiB 的组合可使用 7 位地址 `0x50–0x53`（一颗 2 Mbit）、`0x54–0x57`（第二颗 2 Mbit，取决于第二颗的地址脚连接）。这些地址为典型示例，**不能取代芯片具体型号与接线验证**。读写 64 KiB bank 边界必须重新选址，写入必须按该芯片的页边界分割，以免页内地址回绕覆写已有数据。

现有 [EEPROM 驱动](../src/hal/eeprom.c)：
- 使用 `0xA0 | ((address >> 15) & 0x0E)` 作为 **8 位 I²C 控制字**；它等价于从每个 64 KiB 区间选择 `0x50`、`0x51` 等 7 位器件地址，对某些大容量 banked EEPROM 有效；**不是所有容量及所有 EEPROM 型号的通用公式**。
- 使用两字节内部地址及页边界分块；对 BL24C64A 的低 8 KiB 地址范围可使用两字节字地址。目前**即使探测推算出 256 B 物理页，也保守地以最多 32 B 写块提交**，因为 ACK 计数不能确认真实页大小；这会降低写入速度，但避免把 32 B 页器件当成 256 B 页器件时意外回绕覆盖。
- 通过扫描 `0xA0` 至 `0xAE` 共 8 个偶数地址的 ACK 数量推断：1 → 8 KiB，2 → 16 KiB，4 → 256 KiB，8 → 512 KiB。**这只是当前程序的启发式映射，不是可靠的容量/型号检测**：24C64A 的 A0/A1/A2 为设备选址脚，2 Mbit 芯片将阵列高位编码进控制字；单靠 ACK 无法区分多个小芯片、一个多 bank 芯片或仿真/替代器件。
- 页写完成后有 ACK 轮询，但 `EEPROM_WaitReady(..., 10)` 的实际毫秒行为仍需验证；不可对所有 M24M02 家族武断假设 5 ms。真实 EEPROM 的 WP 脚也可能导致写入拒绝。

后续实现应将 `EEPROM_DetectType()` 的结果视为**候选设备配置**而非确定物理容量。物理型号/容量不明时禁止破坏性扩容探测，不要用“写最后一个地址再读回来”来识别容量：若地址回绕，可能破坏原厂数据。

### 必须保护的存储区域

| 范围 | 含义与证据 | 本项目处理原则 |
| --- | --- | --- |
| `0x0000–0x03FF` | 新 `UVR2` 两份配置，每槽 512 B，见 [config-store.c](../src/core/config-store.c) | 仅用户明确初始化或有效配置授权后写入；CRC 与序号回读校验 |
| `0x1E00–0x1FFF` | 原机校准备份范围。工具 [K5TOOL](https://github.com/qrp73/K5TOOL) 提供读取 `0x1E00` 长度 `0x0200`，并说明其用于校准；[k5prog](https://github.com/sq5bpf/k5prog) 也警告全片覆写的风险 | **默认绝不擦除或覆写**；先备份，不从其他设备复制射频校准 |
| `[容量 - 8840, 容量)` | 本项目旧 Hawk5 SI4732 SSB patch 寻址规则及补丁长度，见 [settings.c](../src/core/settings.c) | 如检测到适配的 patch 则只读使用；写配置时为其保留尾区；不能假定这等于 LOSEHU patch |
| `0x3C228–0x3FFFF` | LOSEHU **2 Mbit** 固件的 15,832 B SI4732 patch 区 | 仅作为其他固件的布局参考，不自动识别为本项目的 patch |

**原厂校准区不是可随意丢弃的旧软件兼容数据**。即使新固件不保留旧频道，也必须保留或通过可信设备备份维护射频校准。当前 `UVR2` 不会主动覆写 `0x1E00–0x1FFF` 或补丁尾区；未来更换 EEPROM、改变用途或完整格式化时同样须保护。

### 新存储设计与验证范围

`UVR2` **不迁移旧 `UVR1` 的编译器位域或旧频道记录**。配置编码为固定字节格式，包含序号、CRC32、设备设置、单工作频率及各频段上次使用的频率/参数和独立模式/步进/带宽/静噪预设。当前为格式 5，新增 RX／TX Tone 和独立 TX Frequency，采用尾部扩展字段；可读取有效格式 4 并保留原参数，新增字段默认 Off／Same，下次保存使用格式 5。其他旧版本不识别，进入用户确认后的初始化流程。两份镜像各 512 B，断电中断写入后可以恢复较早的有效记录。EEPROM 驱动应以实际写入结果返回成功/失败，写入后回读检查。新的配置位置位于低 1024 B，并与原机 `0x1E00–0x1FFF` 校准区分开；这并不授权全片擦除。

**离线已确定**：上述三款芯片的厂商标称容量、页大小、寻址基本模式与写周期，以及 LOSEHU / K5TOOL 在各自固件中的已公开数据布局。

**本台实机待确认**：芯片完整丝印、数量及 A2/A0/A1/WP 接线、EEPROM dump、I²C 控制字应答及只读地址映射、补丁签名与是否需要转换、原厂校准数据及真实写后读回。完成这些核实后，才能给实际设备标记“物理型号/容量已确认”。

建议拿到设备后按**只读优先**：拍摄 8 脚 EEPROM 丝印与扩展板正反面；用受信任且适配所用固件的 K5TOOL/k5prog 工具导出 EEPROM 与 `0x1E00–0x1FFF` 校准数据；记录多个只读地址的实际映射并与芯片数据手册对照；确认补丁签名后，才进行有明确边界的写入验证。

### 写保护基线（开发阶段）

新版固件在 `hal/eeprom-layout.h` 定义唯一可写区域 `0x0000–0x03FF`，两份 UVR2 配置各 512 字节。其他地址（包含 `0x1E00–0x1FFF` 校准区和任何 SSB patch）只能通过读取接口访问；UART 原始 EEPROM 写命令已经禁用。未知 EEPROM 型号按最多 32 B 分块写入。未来若增加 EEPROM 资源管理，应显式设计带确认和备份的独立维护模式，而不是放开通用写入函数。
