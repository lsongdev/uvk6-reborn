## 已采用的优化

1. **字形元数据 8 B → 7 B**：只移除每个 glyph 的末尾填充，点阵、字符范围、间距和字号不变。单独构建由 61,224 B 降至 60,836 B，净省 388 B。Cortex-M0 的奇地址 bitmapOffset 使用 packed 类型读取；检查 ARM 汇编确认为逐字节加载，没有未对齐半字访问。两个现有预览组合（频率／名称、多 VFO／守听）的 PNG 与优化前逐字节相同。
2. **BK4819 接收接口收窄**：生产 HAL 仅需要 NFM、AM，改为 `BK4819_SetRxMode(bool am)`，不携带旧 BK WFM、SSB、bypass 的设置分支；广播 WFM、SSB 的芯片选择不变。接收模式逻辑独立到 `drivers/bk4819/rx.c`，保留原 NFM/AM 写寄存器的值、顺序与缓存行为，增加显式缓存失效入口。单独追加净省 68 B。新回归核对 FM／AM 全部写寄存器、顺序、保留位、切换及失效后重配。
3. **VFO 菜单共用数值显示**：统一生成文本后调用一次右对齐渲染，保持显示单位和操作不变，追加净省 60 B。
4. **停用粗体字库**：通用 8pt 常规体替代少量强调提示的粗体渲染，粗体源文件保留、不参与链接，实际释放 1,240 B。
5. **频道管理收敛与拆分**：将 Name／Save／覆盖选择界面移入 `vfo/channel-manager.c`，移除频道列表、跳号、删除及频道编辑副本；从粗体移除后的 59,468 B 降至 58,124 B，净省 1,344 B。

6. **VFO 模块整理**：VFO 与频道保存移入 `src/vfo/`，卡片视图数据构造与页面渲染分开；Flash 增加 24 B 至 58,148 B，静态 RAM 减少 4 B 至 7,904 B。

保留现有 `-Os`、LTO 和内联策略。对照实验（源代码仅采用字形压缩，除特别注明外）：

| 实验 | Flash | 结论 |
| --- | ---: | --- |
| 未修改字形的 `-Oz` | 61,224 B | 与原始 `-Os` 相同，无收益 |
| 未修改字形，禁止 called-once 内联 | 61,764 B | 比原始增加 540 B，不采用 |
| 未修改字形，再禁止 small-functions 内联 | 64,800 B | 溢出，不采用 |
| 压缩字形，启用标准库 builtin | 61,004 B | 比压缩字形后的 60,836 B 增加 168 B，不采用 |
| 压缩字形，仅 SI SwitchMode 加 noinline | 60,816 B | 净省 20 B；收益小且依赖编译器，不保留 |

其他定点 noinline 实验无收益或增加占用，也不保留。`-Oz` 的目的见 [GCC 优化选项](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html)，本项目实际大小仍以构建为准。

## 后续优化顺序与 FC 门槛

FC 实现前基础镜像有 **3,292 B Flash 余量**。当时 FC 首批规划 1,200–1,800 B Flash、约 128 B RAM；这是当时设计预算；当前实测见文首。FC 实现前基础镜像已低于建议目标 **58,368 B（57 KiB）**，按 1,800 B 上限估算仍有约 1,492 B Flash 余量。

下一轮优先按以下顺序做可测量的结构优化；收益均待逐项构建，不承诺未实测的 KB 数：

1. **芯片配置中的连续常量写寄存器**：比较逐条调用与只读表＋循环。严格保留软复位、读改写、延时、锁定等待和顺序；先核对访问轨迹，不能为了小镜像删除必要硬件动作。
2. **VFO 输入／确认／调谐事务收敛**：频道、Seek、Watch、手动调谐的重复接收恢复与提示逻辑共用实现；不要仅增加包装层。每项操作必须仍有明确来源、选中项归属和失败回滚。
3. **常量字符串和显示路径**：保留用户可理解的错误、单位和确认；检查重复格式化及大型中间状态拷贝。保持现有字体风格，避免为了省空间让频率和名称变成不同字体。
4. **按需外置资源是备选架构**：当前点阵约 2.1 KiB，未来可考虑受管理 EEPROM 区＋manifest／CRC＋小缓存，但需资源安装／升级协议、缺资源恢复、I²C 性能及硬件验收。不能仅将裸数组地址改成 EEPROM 地址，也不建议把整套字库常驻 RAM（当前 RAM 还要留栈空间）。不在本次实施。

真实 TX HAL 尚未接入，当前保留的策略、锁定和 PTT 恢复不能随意删除；旧配置迁移、双副本、CRC、EEPROM 边界及接收失败恢复也不作为删减目标。release 的 Log/LogC 已禁用，进一步关日志没有明显收益。
