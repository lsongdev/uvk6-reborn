# 源码结构

按职责组织文件。项目头文件统一从 `src/` 开始引用，例如 `core/radio-model.h`、`hal/bk4819.h`，避免依赖调用文件所在目录的层数。

| 目录 | 职责 | 主要内容 |
| --- | --- | --- |
| `hal/` | 与具体硬件交互 | 板级 GPIO/ADC 初始化、启动与内存初始化、时钟与定时器、总线、芯片驱动、接收设备适配器 |
| `hal/dp32g030/` | MCU 寄存器定义 | GPIO、UART、DMA、定时器等寄存器地址与位定义 |
| `core/` | 无线电和设备逻辑 | Hz 单位模型、频段匹配、VFO 状态、调谐与恢复流程、设置与配置存储、测量换算、电池状态 |
| `apps/` | 用户操作和应用流程 | 主循环、按键分发、VFO 主界面、频率输入、设置和初始化界面 |
| `ui/` | 显示与交互组件 | 绘图、字体、状态栏、信号条、菜单和数字导航 |
| `config/` | 第三方库编译配置 | printf 等配置头文件 |
| `external/` | 第三方源码 | CMSIS、printf 子模块 |

`main.c` 是固件入口：初始化板级设施，再进入应用主循环。链接脚本 `firmware.ld` 和构建入口 `Makefile` 保留在仓库根目录。主机工具集中在 `tools/`，回归测试集中在 `tests/`。

接收规划与恢复逻辑放在 `core/`；寄存器、I²C 命令、芯片带宽索引转换和实际设备切换放在 `hal/`。例如 `core/radio-model.c` 生成接收方案，`hal/rx-device.c` 将方案应用到具体芯片。

纯逻辑模块 `radio-model`、`radio-state`、`rx-runtime` 和 `config-store` 可独立在主机上验证。现有 `radio`、`settings` 和部分驱动仍有历史交叉依赖；目录整理并不代表已经完成所有接口解耦。后续修改应继续收敛这些依赖，避免将新的硬件协议细节放进纯逻辑模块。

Makefile 显式列出当前启用的应用。历史扫描、频谱及 `memview` 参考代码仍保留在对应目录中，但不进入当前单 VFO 固件构建。
